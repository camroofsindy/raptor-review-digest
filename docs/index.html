Section 2

2. Tactic of the Week

Publish one LocalBusiness + AggregateRating + FAQPage schema block to every existing city service page, starting with the top-six revenue markets today.

WHY — the mechanism:

AI search engines (Google AI Overviews, Perplexity, Bing Copilot) and traditional local-pack ranking both use structured data as a disambiguation signal. When a user queries "roof replacement Carmel Indiana," Google's language model needs to resolve which contractor is geographically and categorically relevant. Schema markup is machine-readable confirmation that removes ambiguity.

ServiceAgent's composite scoring already ranks Raptor #1 in Indianapolis with a score of 8.8/10, while Indy Roof & Restoration ranks #3

— yet Indy Roof surfaces in AI-generated answers and Raptor does not. The structural reason is that Indy Roof's FAQ schema feeds LLM training corpora via Google's structured-data documentation pipeline. Raptor has the reviews and city pages, but the machine-readable layer that signals "this business answers the question being asked" is missing.

HOW — concrete steps (execute today through Friday):

  1. Pull Raptor's six highest-revenue ZIP codes. Based on the site's city page list, start with Carmel, Fishers, Noblesville, Greenwood, Zionsville, and Westfield.
  2. For each city page, write three to five Q&A pairs that match exact natural-language queries. Examples: "How much does a roof replacement cost in Carmel Indiana?" / "Does Raptor Roofing serve Fishers?" / "What roofing materials does Raptor install in Noblesville?" Use tools like AnswerThePublic or Google's "People Also Ask" box for that city name to find real phrasing.
  3. Embed a FAQPage schema JSON-LD block in the <head> of each city page. Simultaneously add a LocalBusiness block with "geo" coordinates, "areaServed" set to the specific city, and an "aggregateRating" block pulling from the live Google review count.

Raptor's Google Maps profile currently shows a 5.0 rating from 663 reviews

— encode that directly and update monthly.
4. Validate every page through Google's Rich Results Test before pushing to production.
5. Submit updated URLs via Google Search Console's URL Inspection tool to force re-crawl within 48 hours rather than waiting for the standard crawl cycle.

This is a two-developer days task, or a single afternoon for a developer familiar with JSON-LD. It does not require a CMS overhaul. It can be shipped page by page.

SUCCESS METRIC — measure at 30 days:

Track three things in parallel. First, run the same six city-specific queries ("roof replacement Carmel Indiana," "roof repair Fishers Indiana," etc.) in a fresh incognito Chrome window and note whether Raptor appears in the People Also Ask or AI Overview panel — baseline that today before any schema goes live. Second, pull Google Search Console's "Search Appearance" filter for Rich Results impressions on those six URLs; a schema implementation that Google accepts will show FAQPage appearance data within 2-3 weeks of crawl. Third, watch city page click-through rate in GSC: FAQ schema typically lifts CTR 10-20% on queries where the snippet expands. If none of those signals move after 30 days, the schema is either malformed or those pages are not being crawled — both are diagnosable.
